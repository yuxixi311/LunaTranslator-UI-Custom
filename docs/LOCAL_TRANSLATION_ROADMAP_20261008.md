# Luna 后续路线：2026-10-08

本路线按依赖关系排列。已授权步骤在操作、目标、数据、范围、费用和风险不变时沿用授权；新权限、明确新拒绝、改变的范围/风险及平台强制逐次确认仍独立处理。公开路线本身不授予操作权限。

## 0. 固定可接续节点

- 使用最终发布 commit 和 [PUBLIC_MANIFEST.json](../tools/local_eval/handoff-20261008/PUBLIC_MANIFEST.json) 核验公开文件；读[总节点](LOCAL_TRANSLATION_CHECKPOINT_20261008.md)。
- 核对既有 ZIP 身份，不重打包、不以新 ZIP 替换它。对本地目录、报告与已消费标记先做只读核对；有不明冲突就停在具体冲突上。
- 历史失败、uncertain 标签、superseded 检查与私有资料缺口分别保留；未检查的证据不标成完整。

完成条件：另一新本地对话能辨认准确源码、准备/真实结果差别、允许的一次操作和停止条件，不依赖旧对话猜测。

## 1. 已获批的一次 Torch 下载与静态检查

严格遵守[本地交接](LOCAL_TRANSLATION_LOCAL_HANDOFF_20261008.md)。已有 Python 3.12、原候选源码、精确授权对象、未消费标记与资源门槛均通过后，只运行 supervisor 一次。至多一个精确 URL 的 GET，无 HEAD/Range/redirect/proxy/probe/重试；4GiB body 上限、独立 4.1GiB 自有磁盘增量上限、900 秒下载和 60 秒静态预算不放宽。

成功条件须同时包括：完整 body 与预期 SHA、成功写入和持久化证据、已确认 worker 零退出、最终 checkpoint、原门槛与静态检查成功。仅有 HTTP 200、parseable JSON、partial journal 或主进程退出都不够。

失败/未知：停止，保留来源、标记、journal、报告与按原规则需保留的文件，报告首错及保留/清理状态；不自动再试。若新本地对话发现此前这一个候选已执行或已有冲突 claim，就分析现有结果，不能当成“新对话”重置单次限制。

## 2. 成功后准备完整依赖闭包及隔离安装方案

获得完整 wheel 只能解除单个资产的证据缺口。先静态核对 metadata/WHEEL/许可、Python/平台/CUDA 标签和依赖约束，再形成完整固定清单：每项精确版本、来源、哈希、字节数、许可及闭包关系。Transformers/PEFT/accelerate 等候选版本不视为已经安装或兼容。不得顺便下载依赖或执行 wheel。

重新核对当时的磁盘/RAM/驱动与可用硬件；明确隔离目录、安装/卸载回退、进程树资源、超时、日志和不污染 Luna 主环境的验证范围。安装与后续环境测试需在具体清单和范围确定后按适用授权执行；这次单 wheel GET 不授权完整环境安装。

完成条件：可审计、可复现、闭包完整的安装提案；实际安装和 import/load 测试在独立获批后才有结果。

## 3. 数据可行性与无污染评价设计

24 条原型保持开发身份，23 暂留 / 1 隔离且全部一个关联组；不能切成训练/测试。Tatoeba 当前 CC0 linked eligible=0，报告不足，不扩大授权或补造对应关系。≤200 对的未来候选需逐对明确来源、权利、审校、版本、歧义及拒绝原因。

按来源、情景、模板、语义近重复形成关联组，再分 train/dev；独立作者另写并冻结最终评价材料。旧实验 fresh 集合仅用于回归。没有合适人工审校时，可单独提出明确标注为模型辅助的无害合成 pipeline smoke 数据，但不得称为高质量语料或用于声称改善；独立分组不足则不启动。

完成条件：权利清楚、分组隔离可复核、用途有限的数据清单与独立评价方案。数据文件与私有评分资料按各自权限保存，不为了“完整归档”公开私人材料。

## 4. 仅在条件补齐后讨论 LoRA 兼容性冒烟

详情为[已归档方案](../tools/local_eval/handoff-20261008/lora/LORA_PLAN_ZH.md)。需先完成官方 trainer 精确源审核、base/tokenizer/template revisions 与哈希、依赖/许可/硬件支持、数据分组和资源终止路径。

当前拟议上限包括：总序列 512、最多 16 个训练样本和另组 8 个开发样本、最多 50 optimizer steps/30 分钟训练、保存释放再重载一次、最多 16 次开发生成。它们是待冻结方案，不是运行授权；BF16 不支持或 OOM 时不自动切 FP16/QLoRA、更换 GPU 或扩大预算。12GB 适配必须在真实 12GB 硬件测量，24GB 卡的低占用不等同于该证明。

云 GPU、模型与依赖下载、训练、费用和具体数据目的地需在边界明确后按适用要求批准；无自动租卡、计费资源、权重下载或训练。完整生命周期还须能证明停止与费用终止；损失下降不能覆盖资源、保存重载或清理失败。

完成条件：仅证明固定管线在固定资源下可用；不据此宣称翻译质量胜出。

## 5. 单独批准质量实验、量化回归与发布

兼容性成功后再决定是否值得训练与独立质量评估；提前冻结改善门槛、重大回归门槛、成本、样本及停止规则。只在未暴露 holdout 上作一次冻结评价；保持基线回退，不据已见例句反复挑胜者。

只有存在明确收益才提出合并高精度底座、固定工具转换/量化为 Q4_K_M、最终量化产物重新质量和性能回归。不能对已有 Q4 重复量化，不能用 BF16 收益代替部署产物收益。另做 Windows UI、加载、延迟、RAM/显存和退出行为验收；默认启用、安装包和权重发布均另行处理。
