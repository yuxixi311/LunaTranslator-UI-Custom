# Three-way harness watchdog repair

The first Windows source-kit check stopped before any Google request, model download, host proof, or GPU run. The original kit matched its frozen hashes. Of 187 discovered tests, 184 passed, one failed, and two optional integration checks were skipped. The failure was the synthetic blocked-read test's assertion that `inference_budget_exceeded` must be true.

The test used a 20 ms budget for the entire post-readiness phase, including 98 fake template/tokenizer exchanges before the intended blocked completion read. It therefore depended on filesystem and thread scheduling speed to reach the intended stage. Separately, the runner recorded budget expiry only from the watchdog timer's callback event. A synchronous request-deadline check could reject work first, after which cleanup canceled the pending timer and incorrectly recorded `inference_budget_exceeded=false`.

A deterministic reproduction of the original code delayed the timer callback while advancing the monotonic clock during probes. It produced the same false budget flag after a request-deadline exception, with zero completion requests and confirmed owned-process cleanup. This establishes the code path; the Windows test's temporary per-case evidence was not retained, so its exact thread scheduling cannot be reconstructed from the archived aggregate log.

The repair retains the frozen 180-second startup and post-readiness budgets, resource reserves, all 48 inputs, model/template pins, and quality rubric. The HTTP client and watchdog now use the same absolute phase deadline. Budget expiry is recorded independently of callback scheduling; separate diagnostic fields record whether the callback fired. An elapsed deadline also raises a terminal error if the last response or final validation otherwise appeared successful. The operation-end time is captured before cleanup, so cleanup duration cannot retroactively make an on-time operation exceed its budget.

The stage tests now control the clock and timer delivery and explicitly assert that the intended blocked health, template, or completion read was reached. They retain the error-wire, incomplete-evidence, budget-expiry, and owned-process-stop assertions. A separate real timer test stops a harmless owned Python child. Additional deterministic cases cover a pending timer callback, delayed timer setup, the last successful response, the final cleanup boundary, and cleanup duration.

Only the three-way runner, its tests, and this note change. The original deadline helper and all historical experiment runners remain byte-identical. The frozen design, data rubric, source fixture, model pins, and all acceptance gates remain unchanged. A new installed-host proof must bind the repaired shared runner before the first Google request.

Cloud validation: 24 focused tests and all 195 tests in the repaired consumer kit pass, including the optional source comparisons when their comparison sources are available. Independent review reproduced the original race, passed the same 24 focused and 195 consumer-kit tests, and found no remaining source blocker. Compilation and whitespace checks also pass. These are consumer-kit checks, not whole-application acceptance tests. The two optional comparisons may still be skipped on a consumer without those external sources. No translation-quality or Windows execution success is claimed by this source repair.
