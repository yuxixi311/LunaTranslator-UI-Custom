# Isolated Hy glossary policy

Experimental source-only preparation; no inference, network, DLL, Qt, user configuration, production edit, default switch, or publication. No held-out source or scoring criteria were inspected. Lexical unit probes are not evaluation fixtures.

## Integration

Transfer glossary_policy.py, production_adapter.py, source_pins.json, and the complete pinned_source/ tree together. The canon remains a separate input with mandatory SHA-256 identity 7cc5bdb3626dd4e781070dca708428c0ef81048d72b067a71f9e15c795814337.

prepare_pair(raw_source, canon_path) returns a frozen Pair with source, matched (tuple of Entry(src,dst)), a, b, matched_count, and messages('A'/'B'). It reads and verifies the fixed canon on every call. Original source must be nonempty, <=200 Unicode code points, one line, and contain no controls. No normalization, trimming, replacement or fallback occurs. The caller must provide the original source: no function can determine provenance of an arbitrary supplied string.

Operational matching executes AST-extracted, hash-pinned production Process.process_before, process_before1, and __createfake. The dictionary is explicit src/dst with whole-word=false and case-sensitive=false. The placeholder intermediate is generated only to prove the real source-selection path; it is never passed to the prompt. Production Sakura.translate is AST-truncated immediately after message creation, with all transport operations omitted; it selects rawtext for Hy-MT2. Operational A and B are rendered by actual LocalHy/Sakura methods plus actual commonbase.checklangzhconv, with Japanese source identity and Chinese target fields supplied by minimal fake language objects. Context is zero; comments are empty. The produced messages must exactly equal the independently expressed frozen prompt strings. More than four matches stops preflight without a completion or fallback.

check_applied_token_counts(a_tokens,b_tokens) validates strict positive integer counts, <=384 each, and B-A<=64. Counts must be real tokenizer measurements over the full applied chat template and generation prefix, not estimates or user-content-only counts. This pure policy function cannot verify their provenance. The runner must obtain them, finish all probes before any completion, compare completion prompt counts, and stop the entire run on any failure. Those execution duties are outside this package.
