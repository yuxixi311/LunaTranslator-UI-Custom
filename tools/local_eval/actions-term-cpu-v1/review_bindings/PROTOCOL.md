# Deterministic terminology: one bounded source proposal

**Decision: one small Python-only synthetic feasibility candidate, pending final design review/freeze; no fresh evaluation fixtures or inference.** The mechanism is guarded masking/restoration for an explicitly declared, unambiguous subset of a supplied glossary. The six safe fictional terms, one globally unsafe homograph entry and their application-wide declarations are fixed in `luna-term-lock-source-proposal-20261006/global_declarations.json` BEFORE independent source authoring. Authors then create source records consistent with those declarations, without selecting safe status per record. Actual product activation separately needs the user's approved glossary and application scope. No current unmet user spelling failure is established.

## Mechanism and admission

Use the supplied exact `src → dst` mappings and explicit application/game scope. Only entries globally declared safe for unconditional terminology rendering in that scope are eligible. The declaration is a supplied constraint, not something inferred from name shape, capitalization, POS, NER, a dictionary hit, or a comment. Existing UI membership alone does not certify that an ordinary-word homograph always denotes the name. The globally unsafe entry stays unsafe for EVERY record, even if a reviewer later finds a particular occurrence to be a person. A same-scope mixed common-word/name surface cannot be relabeled safe per case. Per-record expected sense, gold answer, safe flag and eligibility overrides are forbidden runtime inputs.

Before any scanning or prompt rendering, require 1–4096 source characters and scope ID <=128 characters; an empty/oversized source or oversized scope is a hard input error, not an unbounded nominal fallback. Admission then counts **all exact case-sensitive literal occurrences across ALL supplied glossary entries**, including unsafe entries, allowing overlapping occurrences in the count. Require exactly one total occurrence, no overlap, a globally safe entry and exact source scope. The complete ordered same-scope glossary must equal the frozen declaration projection; a per-record subset, replacement or added entry abstains. Duplicate/conflicting source keys or malformed trusted declarations are hard input errors, never inferred corrections. Count matches and construct the shared glossary block from ORIGINAL source before masking. A/B glossary blocks are byte-identical and retain supplied order. No regex matching, Unicode normalization or case folding is used.

For the admitted source occurrence, replace that exact span with `{LT0}`. Buffer the output, require `{LT0}` exactly once with no other `\{LT[0-9]+\}` token, validate masked structure, restore the fixed canonical target once, then validate original structure. Final output must contain zero unresolved namespace tokens. An original namespace collision abstains; malformed glossary fields containing protected syntax are input errors. The exact conservative source exclusions are any character in CR, LF, `{ } < > %`, any Unicode Pi/Pf quotation mark, and any of `" ' 「 」 『 』`. Adjacent characters of Unicode category L, M or N reject the match. These rules do not recognize semantics and intentionally miss natural Japanese name-plus-particle uses. Widening them would be a material change.

This is a predeclared rendering operation, not replacement of a guessed Chinese name after seeing an error. It guarantees only the inserted string conditional on successful marker conservation. It cannot guarantee that the model put the marker in the right semantic role, or repair tense, negation, causative/passive relations or omitted participants. Never substitute an ordinary-word homograph simply because its spelling appears in the glossary.

Missing/invalid source-observable admission or an over-token-budget input uses the exact existing request, decided before inference. Malformed trusted input and the early hard size bound fail instead of constructing a fallback. A missing, duplicated, changed, invented or unrestored output marker rejects that candidate output; it does not trigger an additional generation, fuzzy matching, guessed repair, reuse of A's already-generated answer, or a falsely successful fallback. Such rejections remain candidate structural failures or incomplete results in the experiment denominator. Restoration can replace only the exact issued token with the fixed canonical destination. Show the source if a future product path needs an untranslated fallback, but do not report it as a translation success.

## Existing support and necessary narrow changes

At application commit `49d3435e95f847a42e0e10053e9155a1695b5432`:

- The noun dictionary already supports global/per-game entries and returns both a glossary and a masked intermediate plus restoration map. Its generated placeholders use `ZX…Z`; matching may be case-insensitive, replacement uses `str.replace`, and restoration is case-insensitive without conservation checks. It is a reusable architectural pattern, not an adequately guarded implementation of this proposal. [Source](https://github.com/yuxixi311/LunaTranslator-UI-Custom/blob/49d3435e95f847a42e0e10053e9155a1695b5432/src/LunaTranslator/transoptimi/noundict.py)
- Hy selects `query_.rawtext`, not the masked `parsedtext`, and renders the matched glossary in the official terminology prompt. Thus existing placeholder code does not currently enforce Hy terminology. Hy's glossary renderer also drops `info`, so a comment cannot silently become a machine-enforced semantic declaration. [Selection and renderer](https://github.com/yuxixi311/LunaTranslator-UI-Custom/blob/49d3435e95f847a42e0e10053e9155a1695b5432/src/LunaTranslator/translator/sakura_base.py#L159-L262)
- The existing local integrity helper can compare exact brace-placeholder multiplicities and protected tags/newlines; its own documentation correctly says it does not score semantics or repair names. A candidate wrapper must validate the masked request/output, restore the one admitted marker, then validate the original source's protected structure. Passing masked output directly to the current original-source check would fail. [Integrity helper](https://github.com/yuxixi311/LunaTranslator-UI-Custom/blob/49d3435e95f847a42e0e10053e9155a1695b5432/src/LunaTranslator/myutils/local_translation_integrity.py), [local wrapper](https://github.com/yuxixi311/LunaTranslator-UI-Custom/blob/49d3435e95f847a42e0e10053e9155a1695b5432/src/LunaTranslator/translator/local_hymt.py#L38-L59)

A pure admission/masking/restoration helper and illustrative fake-only unit tests have now been prepared in `luna-term-lock-source-proposal-20261006/`; their strings are implementation checks, not any part of fresh19. Future integration needs a local-Hy wrapper and explicit declaration/glossary/policy identity in the cache key. Do not silently enable this for other providers, global dictionaries, translated history or result-correction rules. No native adapter, tokenizer dependency, new model or executor redesign is needed. A declaration UI remains separate product scope.

## Difference from the previous glossary pilot

The previous pilot already compared ordinary Hy translation against its existing soft glossary prompt over six fixed fictional names, including homographs. Both arms passed all 12 applicable canonical-spelling checks, so that run establishes **zero measured consistency gain**. Two source-fact fixes were observed, but a new material uncertainty prevented promotion. Preserve that inconclusive result and every prior case as seen; do not regrade the uncertainty. [Public result](https://github.com/yuxixi311/LunaTranslator-UI-Custom/blob/49d3435e95f847a42e0e10053e9155a1695b5432/docs/LOCAL_TRANSLATION_HY_GLOSSARY_RESULT_20261003.md)

This candidate changes how admitted terms are rendered, not merely the same glossary prompt's wording or the earlier POS/NER admission heuristic. The prior 12/12 supplies no observed spelling error to fix and leaves no improvement headroom on those cases. It sets a strong existing-performance reference, not a guarantee on fresh inputs. A fresh independent test can legitimately ask whether guarded rendering preserves fidelity and improves separately scored compliance; it must accept the outcome that A is already fully compliant and no incremental benefit is demonstrated.
