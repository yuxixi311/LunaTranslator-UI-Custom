# Luna Hy1.8B 小规模 LoRA 方案

2026-10-07；仅方案，尚未训练、租用 GPU、下载模型或批准费用。

## 建议

可以考虑 LoRA。建议先验证“数据是否可靠、一次训练能否完整保存和重载”，再判断是否值得扩大。目标只针对漏译、施受关系和否定等语义错误；不承诺超过 Google，也不把训练损失下降当作翻译改善。

保持 Hy-MT2-1.8B 架构和最终 Q4 部署体积方向。训练需使用高精度源权重，不能直接训练现在的 Q4_K_M GGUF。官方[训练指南](https://huggingface.co/tencent/Hy-MT2-1.8B/blob/main/train/README.md)列出1.8B的 LoRA 路径、q/k/v/o 适配器和梯度检查点；其24GB要求对应8192总序列长度。12GB、短序列是待测配置，不是已经证明可行。精确 trainer 源文件本次仍读取失败，不能声称已审核或测试其实现。

## 先把训练数据做好

现有24条是模型辅助编写的开发原型：23条暂可保留，一条词义未解决而隔离；没有人工双语认证。按保守关联图，24条都在同一连通分组，不能拆成“独立训练与测试”。原型及修订完整保留，仅用于检查数据流程，默认不进入首次训练。

已核验的 Tatoeba 日语、中文 CC0 名单与直接翻译链接交集为零，不自动改用更宽授权语料。新的候选数据上限仍为200对，优先原创虚构日语及独立审校中文；不足不补凑。每对记录作者/审校来源、使用与再分发权限、版本、歧义、拒绝原因。模型辅助意见必须与人工审校区分；没有合适人工审校者时，可以另行冻结经过独立模型辅助检查的无害虚构数据，明确只做管线兼容性冒烟；人工审校不是这种技术检查的凭据门槛。但这些数据不能被称作高质量训练集，也不能支持翻译质量改善结论。

重点覆盖六类：人物施受关系、否定/条件/模态、时间与完成状态、数量比较、省略与指代、需要保留的歧义。加入一般句型控制，避免只教一种模板。不得查看旧私有评判细则来造句，不得使用暴露的历史测试、holdout及其改写。由评估负责人单独查重，作者不接触私有测试正文。

先按来源、情景、模板、语义近重复建立关联分组，再划分训练/开发。最终评估由不同作者另行创作并冻结，作者不看训练样本和修订反馈。分组导致样本不足就报告不足，不跨组泄漏。≤200对仅是数据可行性范围，不意味着足够训练，也不预先承诺准确率。

## 第一次只做兼容性冒烟

下面是拟定上限；全部纳入一次审批，不代表现在可以执行。

- 一台指定云端 GPU；专门验证12GB时必须是实际12GB卡，不能把24GB测得的低占用当成12GB实测。用户电脑没有自动获批作为训练机
- BF16 LoRA 为首选，但须先确认硬件和固定软件栈支持；不支持就停止，不在现场自动切FP16/QLoRA。若选FP16，须在冻结方案时明确替代配置及数值检查
- rank8、alpha16、dropout0.05、q/k/v/o适配器、microbatch1、累积4、梯度检查点、关闭KV缓存；种子42；学习率拟定5e-5，优化器拟定AdamW。精确实现与参数名须在源码审查后冻结
- 总序列长度512，含指令、日语和完整中文目标；超长样本预先排除并报告，不截断参考译文。只对助手目标计算损失；全被屏蔽、标签错位立即停止
- 最多16对已完成相应独立检查的训练样本，最多8对另组开发样本；管线专用合成数据须标注其非人工审校状态。样本不足不启动。最多50次optimizer step、累积4，即最多200个microbatch、102400个序列token槽位；30分钟训练窗口先到即停
- 保存一个适配器检查点，释放原模型并确认释放，再从同一底座重载适配器，验证参数/配置/输出流程。最多16次开发集生成（8条基础模型、8条重载后），每次输入≤512、输出≤256，无额外“试一下”调用。这是兼容性检查，不能用这16次结果宣布质量胜出

全生命周期从计费资源可用开始最多90分钟，固定阶段上限：环境/固定资产获取25分钟、校验安装10分钟、加载5分钟、训练30分钟、保存/释放/重载5分钟、开发生成10分钟、清理和确认终止5分钟。未使用的阶段预算不自动转移；全局截止优先。最迟第85分钟停止一切训练、保存及生成工作，立即进入预留的5分钟终止窗口；90分钟包含确认任务和计费资源已终止。若未能确认，记为清理失败并明确报告费用状态未知，不把进程退出等同于停租。下载总量拟定≤12GiB、工作目录≤30GiB、可用宿主RAM至少32GiB、训练进程树RSS≤24GiB、可用磁盘至少40GiB。模型约4.08GB的既有元数据不是完整环境下载清单；若精确依赖/容器清单超过上限，必须在执行前重新核准，不能中途扩大。

每次记录GPU实际总量、峰值allocated/reserved显存、设备空闲余量、宿主RSS、token吞吐、有限损失、适配器变化、保存重载与清理证据。12GB卡建议保留至少1GiB显存余量；OOM、非有限数、哈希/许可/硬件不符、资源不足、阶段超时或清理未证实均判失败并停止。无自动重试、无自动换卡、无自动租期延长。不得因loss下降覆盖兼容性失败。

## LoRA 与 QLoRA 的选择

BF16 LoRA 冻结高精度底座，只训练小适配器；它比较接近官方指南。QLoRA 把训练时底座低比特加载，可能节省显存，但它不是部署GGUF，也不是打开一个开关就保证适配。需额外审核 bitsandbytes、NF4加载、计算dtype、设备支持及 PEFT 的 prepare_model_for_kbit_training 流程。[PEFT官方说明](https://huggingface.co/docs/peft/developer_guides/quantization)提供通用流程，不等于对本模型和本GPU的实测保证。BF16失败后只给出下一方案，不能自动追加QLoRA第二轮。

## 执行地点与费用

优先指定云端环境，暂未选定供应商、账户或可操作的连接。GitHub普通CPU实验结果不能证明GPU训练环境可用。已有12GB卡的免费本地路线只有用户另行明确选择电脑/执行范围后才考虑；电力、时间成本也不是零。

供比较，2026-10-07读取的[Runpod官方价格页](https://www.runpod.io/pricing)列出24GB RTX A5000 $0.27/小时、RTX3090 $0.50/小时，容器磁盘 $0.10/GB/月。这些是页面标价，不保证库存、区域、税费或实际结算。90分钟纯GPU算术分别约$0.405/$0.75，未含存储等；它们可测试训练流程，但不能验证实际12GB适配。

建议首次审批讨论上限为总计US$5，包括GPU、设置期间计费、存储、传输和税费；这是提议，不是已获批或提供商账单硬限。必须在下单前核实实际GPU/小时价、最低充值、预付是否可退、停止与删除磁盘后的计费、取消规则及预算控制。若最低充值或总承诺超过批准金额则不购买。只有任务脚本计时而不能确认资源停租，不能宣称具备费用硬保护。若没有可验证的停租与计费控制，就不启动；不创建默认持续计费卷、公开端点或自动续租。

## 精确冻结与部署回归

启动前仍缺：源权重完整revision与SHA、tokenizer/模板/配置哈希、官方trainer实际源码审核、Python/PyTorch/Transformers/PEFT/CUDA及其依赖版本/许可/镜像摘要、GPU型号/驱动、数据分组与审校签名、终止资源和账单核验路径。下载URL、域名/跳转与字节上限和失败行为也要写入冻结清单。当前方案不伪造这些pin；缺一项就不执行。

冒烟成功后只证明流程可用。更大训练轮次、样本数和预算另据吞吐/审校成本提出。质量评估在未接触的独立分组上进行：基础模型与候选使用相同提示/解码，统计漏译、关系、否定、添加信息、格式和不确定项；预先定改善与零新重大回归门槛。开发集选checkpoint，测试集只作冻结后的评价，不能反复挑最好结果。

若有明确收益，再把适配器合并到同一高精度底座，通过固定[llama.cpp转换/量化工具](https://github.com/ggml-org/llama.cpp/tree/master/tools/quantize)生成Q4_K_M；重新评价最终量化产物，不能只评价BF16。禁止反复量化已有Q4。检查GGUF大小、tokenizer/模板、加载兼容、源语义/格式回归，再由另行批准的Windows硬件测试量测延迟/RSS/显存。自动默认启用、发布权重和安装包均不包含在本方案内，现有baseline始终可回退。
