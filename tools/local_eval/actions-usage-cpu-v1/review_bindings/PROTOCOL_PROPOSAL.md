## Rationale and alternative

Test at most one materially different mechanism: a single intact Japanese–Simplified Chinese usage example selected by a source phrase. A contextual aligned example might supply a useful translation pattern absent from a broad dictionary sense list. It can also import the wrong meaning, roles or wording; exact overlap is not semantic proof.

Conservative sentence splitting is not proposed. Sentence boundaries do not establish independence of negation, participants, ellipsis or discourse. Separate translation calls increase cost; formatting the same sentences inside one prompt adds no new lexical evidence. There is no source-grounded reason here to expect it to solve the observed problem safely.

The previous broad prefix remains a failure: 39/48 baseline whole-row passes for both reviewers versus 35/48 and 34/48 candidate passes; two consensus regressions, no consensus critical-to-whole-row fixes, and failed elapsed-cost gates. The retrieval paper provides mixed evidence on XGLM-7.5B in other language/domain settings, not validation for Japanese–Chinese Hy1.8B. No default or release promotion follows from this proposal.

## Proposed bank and mechanism

1. Obtain exactly eight intact, directly aligned, independently vetted public sentence pairs. Conservative discovery bounds are at most 16 Japanese and 12 Chinese Unicode characters; these are filters, not token guarantees. Do not chop clauses, paraphrase examples, repair their meaning or infer alignment through a third language. Already Simplified Chinese is usable; a complete Traditional-to-Simplified orthographic adaptation is allowed only through the explicit pre-freeze contract below.
2. Preserve the exact captured original Japanese and Chinese texts, page URL/title/section, capture date and text hash, observed license and supplied visible notices. Verify direct alignment, applicable reuse/attribution requirements, standalone meaning and bilingual adequacy. Wikimedia page-URL attribution can support current-page reuse; a failed history/permalink fetch is not by itself disqualifying. Clearly label a displayed revision as observed metadata, not independent retrieval or attestation of immutable revision bytes. Record failed reads and unknown provenance honestly. A text hash pins the captured bytes, not their historical authenticity. Store notices separately from the prompt; community provenance alone is insufficient.
   - For an orthographic adaptation, retain the full original Chinese and full converted Chinese, plus a position-by-position mapping from every original Unicode character to resulting character(s), including unchanged positions and target offsets. Retain source evidence and an explicit modification notice; apply the source license, including CC BY-SA obligations where applicable.
   - An independent bilingual reviewer must approve every changed mapping and the complete pair's unchanged meaning, roles, negation and register. No Japanese edit, punctuation change, deletion, truncation, paraphrase, meaning repair or token-saving rewrite is permitted. Unjustifiable context-sensitive conversion rejects the pair. Do not claim the source originally supplied Simplified text.
   - Freeze original/candidate text, complete mapping, notices, source evidence, reviewer acceptance and adaptation policy with the bank, before evaluation fixtures or outputs. Proposed/pending pairs are not approved bank entries.
3. Each entry has one fixed contextual Japanese phrase anchor and a designated lexical focus. Independent source-only review must explain why the anchor contains meaningful context beyond that focus alone. No headword-only matching, corpus-wide search, BM25 ranking, embeddings, lemmatization, sense model or output-based selection.
4. Matching is exact, case-sensitive Unicode substring matching against the unmodified source: no Unicode normalization, script conversion, whitespace folding, punctuation replacement or other normalization. An input is surface-eligible only if exactly one bank record matches, its anchor occurs exactly once, its designated focus has no occurrence outside that anchor, and `myutils.local_translation_integrity.needs_integrity_check(raw_source)` from the pinned production adapter does not identify protected structure. The complete finite predicate for competing registered usages is: two or more frozen bank record IDs have an exact anchor substring in the source. There is no additional semantic or extensible exception predicate. Multiple records, repeated occurrences, protected structure, sources over 4,096 characters or out-of-scope baseline configurations abstain. Do not use longest-match or preferred-record tie breaking.
5. These are observable conditions, not an ambiguity detector. A unique match can still be literal, quoted, metalinguistic, polarity-sensitive or inappropriate. Tests must expose those cases rather than treating them as automatically resolved. Unregistered ambiguity cannot be promised to abstain.
6. For an admitted input, prepend exactly `译例：{complete Japanese}→{complete Chinese}\n\n` to the unchanged baseline user-message content. The displayed escape notation denotes actual newlines. Add no other instruction, definition or context. Keep the original source byte-for-byte and retain the existing output guard.
7. Freeze one bank, one matching policy, one wrapper and one parameter set. No alternate prompt, case exception, answer repair, adaptive retry or output selection. Any abstention returns the exact existing baseline request, with its reason retained.

## Proposed token and elapsed-cost limits

The proposed admission limit is Δ ≤ min(16, floor(0.40 × B)), where B is the real token count of the complete baseline chat template and Δ is the difference for the complete candidate template, including wrapper and generation markers. Also require candidate total ≤384 tokens. A baseline over 384, an unknown template/tokenizer or a failed real token count blocks the attempt before generation; do not drop the row. No source lengthening, unrelated sentence merging or example truncation is permitted to force admission.

This absolute addition is fourfold smaller than the failed 64-token allowance. The supplied prior baseline range of 29–54 tokens would permit 11–16 added tokens. The 40% input bound is a proposed screening constraint, not a user requirement or a latency model. Prior input/elapsed correlations do not establish causation or predict a pass. Actual token feasibility is unknown.

Keep the real end-to-end gate unchanged: both median and nearest-rank P95 of per-row candidate/baseline elapsed ratios must be ≤1.25 in all four populations: fresh, active fresh, all, and all active. An active row is one whose example is admitted and injected according to the completed preflight; that membership is fixed before generation. Output-guard rejection, later translation failure or adverse judgment never removes it from an active stratum. Include candidate lookup, rendering, required token counts, generation and unchanged output validation. Report raw timings, prompt/output tokens and AB/BA effects. No ratio of aggregate quantiles, subtraction of helper overhead, exclusion of fallbacks, or empty-active-stratum pass. Missing, invalid, timeout-truncated or materially unstable observations make the attempt incomplete/inconclusive unless another definite gate failure already decides it.

## Independent fixtures and semantic gates

Only after bank verification and mechanism review/freeze, commission independently authored sources and private source-grounded criteria. The designer/implementation worker must not read private answers, ratings or arm mapping. A bank-preferred sense cannot make a source-permitted alternative wrong.

- 32 new rows in eight anchor families: two natural, genuinely new carrier contexts, one matched challenge and one boundary/abstention control per family. Avoid bank sentences and source-derived paraphrases as independent holdouts; do not manufacture unusually long carriers to pass the token bound.
- Preserve all 40 published historical regression rows, plus at most 16 root-supplied seen critical/uncertain regression rows. If all relevant additional cases cannot fit, stop for a scope adjustment rather than silently omit them. Seen rows receive no fresh-improvement credit. Preserve all prior results and uncertainty.
- Proposed pre-output coverage: at least 12/16 carrier rows active, with both carriers active in at least six families. Prescribed surface-rule abstentions must be correct. Publish/retain all activation decisions and reasons before any completion. Failure stops the attempt without changing the bank, rules or fixtures.
- Assign the eight matched challenges to six predeclared primary types: literal use, metalinguistic use, polarity, argument/participant assignment, source ambiguity, and otherwise inappropriate usage. Require at least one preflight-active challenge in EACH type (therefore at least six of eight active). The remaining two challenges repeat two types selected by the independent author before outputs. One row counts toward exactly one primary-type quota; additional descriptive tags cannot satisfy another quota. These source-grounded labels are frozen fixture-coverage metadata only, never runtime sense labels or an input to retrieval. Define the inappropriate-usage case from its source independently of the retrieved example; do not invent a single required reading for ambiguous sources. Protected markup, competing records and repeated occurrences remain explicit control/regression coverage. Abstention cannot hide an entire matched risk type; missing a type after actual token admission stops the unchanged attempt. All cases fit within the fixed 32 new rows.
- Require at least two independently agreed definite critical-error-to-whole-row-faithful-pass fixes on fresh active rows, across distinct anchors and lexical families. Require zero definite new material whole-sentence meaning regressions and zero new structural failures across every row, including sibling contexts and seen regressions; this includes material noncritical errors as well as critical errors. A regression is a dimension that the baseline definitely preserves but the candidate materially violates. Moving an existing error to another dimension still counts. Report all remaining failures. Unresolved material judgments remain inconclusive; fluency cannot offset semantic harm. Use independent label/order review and disclose its actual blinding limits.

## One future job only: requests and resources

No separate token-only job, reacquisition stage or extra inference screen is proposed. After the source-only fixture set is frozen, compute M (total paired rows) and E (surface-eligible rows before token admission) without answers or model calls. Freeze the exact request inventory before execution review; 530 is only its theoretical maximum, not permission to consume spare requests.

- M = 32 + 40 + R, with 0 ≤ R ≤16; hence M ≤88
- Health and model identity: exactly 2 requests
- Complete preflight: exactly 2M token-count requests, including the planned baseline-equivalent count for an ineligible row
- Measured execution: exactly 2M translation completions and 2E required candidate token-count requests, including token-budget fallbacks
- Exact full-run inventory: 2 + 4M + 2E ≤530 requests; translation completions ≤176

Preflight must verify every actual template count, admission decision and coverage gate before the first completion. Any preflight failure terminates that attempt with fewer consumed requests and zero translations. It does not authorize replacement examples, fresh sources, changed gates or extra calls. No warm-up generations or retries. Recheck/bind token-count receipts during the measured candidate interval according to the fixed 2E inventory; preflight work must not conceal runtime costs.

Use only the existing pinned Hy1.8B Q4 model and existing pinned runtime on cloud CPU: one server slot, unchanged sampling, seed, context-free/no-glossary configuration, output cap and guard. Missing/mismatched assets stop the work; no downloads, installs, GPU, paid APIs, larger model or training.
