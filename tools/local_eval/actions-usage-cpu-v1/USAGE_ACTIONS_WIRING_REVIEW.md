# Enabled usage Actions source wiring

This is source preparation in a new derivative directory. It creates no GitHub
workflow object, commit, publication, dispatch, claim, child, tokenizer request,
or generation. The unchanged cc31 source package and previously published
runner are separate inputs, not mutation targets.

## Concrete invocation path

The inert `WORKFLOW_TEMPLATE.yml.in` keeps the existing branch
`experiment/luna-actions-lexical-20261005` and selects only
`.github/workflows/luna-usage-cpu-v1.yml`. Its project is
`tools/local_eval/actions-usage-cpu-v1`; the independent temporary state name is
`luna-usage-cpu-20261006-v1`. The job is `usage` on `ubuntu-24.04`, with the existing
30-minute job timeout, read-only contents permission, pinned checkout action,
no stored credentials, and no container/cache/upload/dispatch step.

The absolute isolated bootstrap command verifies the complete module byte
closure before importing it. `actions_entry` then verifies every manifest file,
the exact source-only A tree and A parent, the sole workflow addition at B,
the exact expanded workflow bytes, the provider event, and first run attempt.
Only then can it install a process-bound Actions grant. Import, environment
variables, or a matching-looking CLI alone cannot grant native access.

`final_coordinator.run_stages` retains the owned acquisition worker, archive/ELF
validation worker, pinned runtime version process, prelaunch resource/host
recheck, and owned CPU server. It then invokes:

1. `usage_runtime_inventory.load` for the pinned 87-row public inventory and a
   parent facade that never executes matching or bank lookup
2. `usage_worker_packets.create_worker_packet_factory` for the exact bounded,
   exclusive, sealed helper closure/binding files
3. `usage_native_adapter.bind_native_hooks` with the existing supervisor and
   independent `AttemptControl`
4. `usage_native_adapter.generation_stage`, using the 87-row usage ledger,
   persistent worker and final evidence reconciliation

The legacy 88-row loader, lexicon, scientific stage, reconciliation and public
exporter are not called. The old isolated-helper bootstrap role is rejected.
The new worker entry validates its own pinned closure and direct parent claim.
Initial and final public records use only `usage_public_exports`' closed schema.
Missing ledger evidence remains unknown, never a fabricated zero.

## Explicit unresolved release bindings

Source commit A, activation commit B, reviewed source parent and attempt UUIDv4
must be bound during a separately authorized
release. B cannot contain its own hash: its identity is the actual provider SHA,
verified against checkout, workflow SHA, sole changed path and parent A.
The observed parent `c23ef956fe80bda629d90915332c0feac33d061a` is a read-only
observation, not a fabricated source or activation commit.

`INPUT_COMMITMENTS.json` must have exactly `source_parent`, `attempt_id`, and
`commitments`. Placeholders fail admission before any attempt or acquisition.
Provider checks retain the existing standard GitHub-hosted Ubuntu 24.04,
Linux/X64 scope and a nonempty observed image-version provenance field, with no
prior image-version pin or attestation prerequisite. Actual host namespaces,
capacity, library hashes, cgroup ancestry, TLS, archive paths, resources and
deadlines remain separately checked by the retained operational code.

The final operational-contract digest is also a required source binding; it
must identify the finalized new contract, never substitute an old experiment's
approval or a synthetic SHA.

## Cleanup evidence and residual backstop

The existing owned supervisor/controller handles are the primary cleanup path.
Unknown spawn/adoption/exit/reap outcomes remain incomplete with cleanup
unconfirmed. Neither a source test nor GitHub runner process-marker cleanup
proves timely teardown. Standard GitHub-hosted ephemeral Ubuntu VM job timeout
and eventual decommissioning are only the accepted residual backstop; they do
not prove the 600-second helper lifetime, 20-second cleanup bound, or no orphan
after an unconfirmed OS operation.
